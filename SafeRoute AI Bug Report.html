🔴 Critical Bugs (4)
  • Security Hardcoded Weak Secret Key in Production
    backend/app/core/config.py:29

    The SECRET_KEY uses a hardcoded, weak default value ("your-secret-key-change-in-production"). If deployed without environment variable override, attackers can forge JWT tokens and impersonate any user.

    Impact: Complete authentication bypass - attackers can forge tokens for any user

    SECRET_KEY: str = "your-secret-key-change-in-production" # CRITICAL: Weak default # SOLUTION: Require environment variable, fail if not set SECRET_KEY: str = "" class Config: @classmethod def validate_secret(cls, v): if not v or len(v) < 32: raise ValueError("SECRET_KEY must be at least 32 characters") return v
  • API Authorization Bypass - Anyone Can Delete Any Report
    backend/app/api/v1/endpoints/hazards.py:90-105

    The delete_report endpoint fetches a report and deletes it WITHOUT verifying that the current user owns the report. There's even a TODO comment acknowledging this issue.

    Impact: Any authenticated user can delete any other user's reports

    @router.delete("/reports/{report_id}", status_code=status.HTTP_204_NO_CONTENT) async def delete_report(...): report = await hazard_service.get_report(report_id) if report is None: raise HTTPException(status_code=404, detail="Report not found") # TODO: Check if report belongs to current user # CRITICAL: Missing auth check! await hazard_service.delete_report(report_id) # SOLUTION: Verify ownership before deletion if str(report.reporter_id) != str(current_user.id): raise HTTPException(status_code=403, detail="Not authorized to delete this report")
  • Security CORS Allows All Origins in Production
    backend/app/core/config.py:21

    CORS_ORIGINS defaults to ["*"] allowing any website to make requests to the API. This enables CSRF attacks and credential theft via malicious websites.

    Impact: Cross-site attacks, potential credential theft via malicious websites

    CORS_ORIGINS: List[str] = ["*"] # Allows ANY origin # SOLUTION: Restrict to known origins CORS_ORIGINS: List[str] = [] class Config: env_file = ".env" # In production, require explicit origins @validator('CORS_ORIGINS', pre=True) def parse_cors(cls, v): if isinstance(v, str): return [origin.strip() for origin in v.split(',')] return v or []
  • Android Localhost API URL Won't Work on Real Devices
    android/app/build.gradle.kts:42, 63

🟠 High Severity Bugs (7)
  • Database SQL Injection Risk in Hazard Aggregation
    backend/app/services/hazard_service.py:107-119

    Raw string interpolation is used to build PostGIS queries with report.location.longitude and report.location.latitude. While SQLAlchemy's GeoAlchemy2 may handle this, the pattern is dangerous and bypasses ORM parameterization.

    Impact: Potential SQL injection through location data

  • API No Rate Limiting Implementation
    backend/app/main.py, backend/app/core/config.py:48

    RATE_LIMIT_PER_MINUTE is configured but never actually implemented in the application. The application has no rate limiting middleware or decorators.

    Impact: API vulnerable to brute force and DDoS attacks

  • Android Token Never Refreshed - Session Expires Silently
    android/app/src/main/java/com/saferoute/data/remote/ApiClient.kt:55-69

    The Ktor Auth plugin is configured with loadTokens but no refreshTokens handler. When the access token expires (after 7 days), the app will start receiving 401 errors with no automatic recovery.

    Impact: Users will be logged out unexpectedly, poor UX

  • Database Database Connection Pool Not Configured for AsyncPG
    backend/app/core/database.py:13-18

    The asyncpg engine is created with pool_size and max_overflow parameters, but asyncpg uses different parameter names (min_size, max_size). The current config won't apply.

    Impact: Connection pool may exhaust under load, causing timeouts

  • API Firebase Auth Not Implemented - 501 Error Always Returned
    backend/app/api/v1/endpoints/auth.py:101-112

    The firebase_login endpoint always raises HTTP 501 (Not Implemented). Users cannot authenticate with Firebase, blocking a key authentication pathway.

    Impact: Firebase authentication is completely non-functional

  • Android Location Permission Check Missing in Service
    android/app/src/main/java/com/saferoute/service/LocationTrackingService.kt:125-134

    The service catches SecurityException but only stops itself. The exception should propagate to the UI so the user can be prompted to grant permissions properly.

    Impact: Poor UX - service dies silently without user notification

  • API User ID Type Conversion Bug in get_by_id
    backend/app/services/user_service.py:20-23

    The get_by_id method accepts a string user_id but tries to convert it to UUID. However, the JWT token stores user ID as a string, and if the token has a malformed UUID, this will throw an unhandled ValueError.

    Impact: Unhandled exception crashes request on invalid UUID format

    async def get_by_id(self, user_id: str) -> Optional[User]: result = await self.db.execute(select(User).where(User.id == UUID(user_id))) # If user_id is "invalid-uuid", raises ValueError from uuid import UUID, InvalidUUID async def get_by_id(self, user_id: str) -> Optional[User]: try: uuid = UUID(user_id) except (ValueError, InvalidUUID): return None result = await self.db.execute(select(User).where(User.id == uuid))
🟡 Medium Severity Bugs (8)
  • Config Port Mismatch in Docker Compose vs Documentation
    infrastructure/docker/docker-compose.yml:13

    PostgreSQL is mapped to port 5433 on the host, but documentation says 5432. This mismatch will confuse developers following the README.

    Impact: Developer confusion, connection failures

  • Database No Database Index on location Column for Spatial Queries
    backend/app/models/hazard.py:65

    The location column uses PostGIS Geometry but has no spatial index (GIST). Nearby hazard queries will perform full table scans, causing performance issues at scale.

    Impact: Slow queries as hazard data grows

    from geoalchemy2 import Geometry from sqlalchemy import Index class Hazard(Base): __tablename__ = "hazards" location = Column(Geometry("POINT", srid=4326), nullable=False) __table_args__ = ( Index('idx_hazard_location', 'location', postgresql_using='gist'), )
  • API No Input Sanitization on Description Fields
    backend/app/schemas/hazard.py:55-64

    Hazard report descriptions are stored without XSS sanitization. While the API returns JSON, if this data is ever rendered in HTML without escaping, it could lead to stored XSS attacks.

    Impact: Potential XSS if data rendered unsafely in future

  • Android Device ID Regenerated on Every Login
    android/app/src/main/java/com/saferoute/ui/screens/LoginScreen.kt:103

    A new UUID is generated for device_id on every login. This makes it impossible to track anonymous users across sessions, breaking analytics and fraud detection.

    Impact: Cannot track anonymous users, broken analytics

  • API Inconsistent Error Handling - Some Routes Return Wrong Status
    backend/app/services/user_service.py:85-94

    The delete method returns False when user not found, but the endpoint (users.py:39-46) doesn't check this return value, resulting in 204 No Content even when the user didn't exist.

    Impact: Client receives success for non-existent resource deletion

  • Config Debug Mode Enabled by Default
    backend/app/core/config.py:14

    DEBUG defaults to False which is good, but there's no environment-based override protection. A common mistake is deploying with DEBUG=true in environment.

    Impact: Risk of exposing debug info in production

  • Android SpeedCalculator Never Clears Old Readings on Large Time Gaps
    android/app/src/main/java/com/saferoute/navigation/SpeedCalculator.kt:20-42

    Readings older than a certain threshold should be invalidated, but the calculator only checks windowSize. If GPS is off for an hour then comes back, old readings will still affect the average.

    Impact: Incorrect speed calculations after GPS gaps

  • Database Hazard Reports media_urls Stored as Comma-Separated String
    backend/app/models/hazard.py:107

    media_urls is stored as a String(1024) with comma-separated values. This is denormalized and limits the number of URLs. Should be a separate table or JSONB.

    Impact: Limited media attachments, difficult to query individual URLs
